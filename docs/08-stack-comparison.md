## รายละเอียดแต่ละตัวเลือก

### A. Astro + Cloudflare Workers/D1/R2 ✅ แนะนำ

**ข้อดี**
- Astro สร้างหน้าสาธารณะเป็น HTML สำเร็จรูปที่แทบไม่มี JavaScript จึงเร็วที่สุดบนมือถือและดีต่อ SEO ส่วนหลังบ้านใช้ React เป็น "island" ในโปรเจกต์เดียวกัน
- `wrangler`/`astro dev` จำลอง Workers, D1 และ R2 **บนเครื่องได้ครบ** ไม่ต้องสมัครอะไร
- Free tier ของ Cloudflare **ใช้เชิงพาณิชย์ได้**, ไม่หยุดโปรเจกต์อัตโนมัติ และไม่มี cold start ที่รู้สึกได้
- repo เดียว deploy ที่เดียว ใช้ D1 Time Travel กู้ข้อมูลย้อนหลังได้ และ rollback ด้วยคำสั่งเดียว
- ใช้ Drizzle + TypeScript เหมือน metafarm-next

**ข้อเสีย / ความเสี่ยง**
- Workers ไม่ใช่ Node เต็มรูปแบบ ไลบรารีบางตัวใช้ไม่ได้ เช่น `sharp` สำหรับย่อรูป → **แก้ด้วยการย่อรูปบนเบราว์เซอร์ก่อนอัปโหลด**
- D1 เป็น SQLite ไม่มีฟีเจอร์ขั้นสูงของ Postgres แต่งานนี้ไม่ได้ใช้
- ผูกกับ Cloudflare ค่อนข้างมาก → **แก้ด้วยการเขียน logic เป็น TypeScript ธรรมดา + Drizzle** ถ้าต้องย้ายก็ไปใช้ Node + SQLite/libSQL ได้
- ต้องเขียนหน้าหลังบ้านเอง (ไม่มี admin UI สำเร็จรูป)

### B. Next.js + Vercel + Supabase

**ข้อดี:** ecosystem ใหญ่ที่สุด มีตัวอย่างเยอะ และ Supabase ให้ Auth + Storage + Postgres สำเร็จรูป
**ข้อเสียที่ตัดสิน:**
- **Vercel Hobby (ฟรี) ห้ามใช้เชิงพาณิชย์** ถ้าขายของต้องใช้ Pro ($20/เดือน) จึงขัดกับเงื่อนไขข้อ 1 และ 6
- **Supabase free หยุดโปรเจกต์อัตโนมัติเมื่อไม่มีการใช้งาน 7 วัน** ซึ่งเสี่ยงช่วงที่เจ้าของฟาร์มไม่ได้เข้าหลังบ้าน
- จำลอง Supabase บนเครื่องต้องใช้ Docker หลายคอนเทนเนอร์ ซึ่งหนักสำหรับเครื่องพัฒนา

### C. SPA + API แยก + Neon (แนวเดียวกับ metafarm-next)

**ข้อดี:** คุ้นเคยที่สุด, Postgres เต็มรูปแบบ และ Neon free ไม่หยุดโปรเจกต์ถาวร
**ข้อเสีย:**
- SPA ทำให้หน้าสาธารณะช้ากว่าและ SEO แย่กว่า ถ้าต้องการ SEO ต้องเพิ่ม prerender เอง (metafarm-next ต้องเขียน `prerender-public` แยก)
- ใช้สองผู้ให้บริการ (Cloudflare + Neon) และ local ต้องต่อ Neon branch จริงหรือรัน Postgres เอง
- Neon free มีพื้นที่ 0.5 GB และ compute หลับเมื่อไม่ใช้ ทำให้ request แรกช้า

### D. Astro + PocketBase

**ข้อดี:** PocketBase มีหน้า admin, auth และอัปโหลดไฟล์**สำเร็จรูป** จึงอาจได้หลังบ้านใช้งานภายในไม่กี่วัน และรันบนเครื่องได้ง่ายเพราะเป็นไฟล์เดียว
**ข้อเสีย:**
- ต้องมี **เซิร์ฟเวอร์รันตลอดเวลา**: VPS ฟรีอย่าง Oracle Cloud ต้องผูกบัตรและดูแล OS/backup เอง ส่วนแบบเสียเงินถูกสุดประมาณ 150–200 บาท/เดือน
- หน้า admin สำเร็จรูปเป็นตารางแบบ generic ซึ่งเจ้าของฟาร์มใช้บนมือถือไม่สะดวก สุดท้ายก็ต้องทำหน้าหลังบ้านเองอยู่ดี
- ภาษา/ecosystem (Go + JS hooks) ต่างจากที่คุ้นเคย

### E. Laravel/Django บน VPS

**ข้อดี:** ครบในตัว มี admin (Django) และย้ายไปไหนก็ได้
**ข้อเสีย:** ต้องจ่ายค่า VPS, ดูแลเซิร์ฟเวอร์ ความปลอดภัย SSL และ backup เอง เกินความจำเป็นสำหรับทีม 1–3 คน

### F. No-code (AppSheet/Sheets + WordPress/Google Sites)

**ข้อดี:** เริ่มได้เร็วที่สุด และเจ้าของฟาร์มคุ้นกับ Excel อยู่แล้ว
**ข้อเสีย:** ทำ "สมุดพกชันโรง" (หน้าสาธารณะต่อรัง + QR) และสายพันธุ์รังแม่/รังลูกได้ยาก, AppSheet แบบฟรีเหมาะกับต้นแบบเท่านั้น, ย้ายข้อมูลออกยาก และหน้าเว็บช้า/SEO จำกัด
→ เหมาะเป็น**ตัวสำรอง**ถ้าไม่อยากเขียนโค้ดเลย

## เหตุผลที่แนะนำ A

1. **เป็นตัวเลือกเดียวที่ผ่านเงื่อนไขหลักครบ:** ฟรี + ขายของได้ + ไม่หลับ + local ครบ ตัวเลือกอื่นติดอย่างน้อยหนึ่งข้อ (B ห้ามเชิงพาณิชย์, D/E ต้องมีเซิร์ฟเวอร์, C ต้องใช้สองผู้ให้บริการ)
2. **ลักษณะงานเหมาะกับ Astro:** เว็บนี้ส่วนใหญ่เป็นเนื้อหาที่ต้องอ่านเร็ว (หน้าแรก ความรู้ อบรม สมุดพก 150 หน้า) ส่วนที่โต้ตอบเยอะมีแค่หลังบ้าน การทำทั้งเว็บเป็น SPA (B/C) จึงเกินความจำเป็น
3. **ขนาดข้อมูลเหมาะกับ SQLite:** 150 รังและหลักพันเหตุการณ์ D1 รองรับได้สบาย และ query ใกล้ผู้ใช้
4. **ต้นทุนเป็นศูนย์จนกว่าจะพร้อม:** ใช้โดเมน `*.workers.dev` ฟรีไปก่อน ค่อยซื้อโดเมนจริงตอนเปิดตัว
5. **ความเสี่ยงหลักแก้ได้:** ผูกกับ Cloudflare → แยก logic ออกจาก runtime และใช้ Drizzle ซึ่งย้ายไป SQLite/libSQL ได้

**ถ้าเงื่อนไขเปลี่ยน:**
- อยากได้หลังบ้านเร็วที่สุดและยอมจ่ายค่า VPS เล็กน้อย → **D (PocketBase)**
- อยากใช้โค้ดหรือรูปแบบเดียวกับ metafarm-next ให้มากที่สุด → **C** แต่ต้องเพิ่ม prerender ให้หน้าสาธารณะ
- ไม่อยากเขียนโค้ด → **F** เป็นทางชั่วคราว

## แผน Deploy ของตัวเลือก A

```
[เครื่องตัวเอง]  pnpm dev  (D1/R2 จำลองใน .wrangler/)  ← ช่วง Phase 1–2 อยู่ตรงนี้ทั้งหมด
       │ git push
       ▼
[GitHub private repo] ── Actions: lint · typecheck · test · build
       │                    │
       │ PR                 └─▶ Preview  (D1 / R2 ชุด preview)  →  ลิงก์ให้เจ้าของฟาร์มลองก่อน
       │ merge main
       ▼
   migrate D1 (prod) ─▶ deploy Worker (prod) ─▶ smoke test ─▶ ถ้าพัง: wrangler rollback
       │
       └─▶ ทุกคืน: d1 export → R2 bucket "backups" (เก็บ 30 วัน) + D1 Time Travel
```

| ขั้น | เมื่อไร | ค่าใช้จ่าย |
|---|---|---|
| Local เท่านั้น | Phase 1–2 | 0 |
| สมัคร Cloudflare + GitHub แล้ว deploy ไปที่ `metafarm.<account>.workers.dev` | Phase 3 | 0 |
| ซื้อโดเมนผ่าน Cloudflare Registrar แล้วผูกกับ Worker | ตอนเปิดตัว | ประมาณ 400 บาท/ปี (.com) |
