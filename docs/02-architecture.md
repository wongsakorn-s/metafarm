# Architecture

> Stack: **Astro 7 + Tailwind 4 · Cloudflare Workers · D1 + Drizzle · R2** (ไม่ใช้ React — เอาออก 2026-10-10 · เหตุผลเลือก stack อยู่ใน [08-stack-comparison.md](08-stack-comparison.md))

## โครงสร้างระบบ

```
 ลูกค้า (มือถือ) ──▶  เว็บสาธารณะ  (HTML เร็ว, SEO)      /, /products, /passport/:code …
                          │ อ่านข้อมูลผ่าน "public queries" (ตัดฟิลด์ 🔒 ออกเสมอ)
                          ▼
                      ฐานข้อมูล + ที่เก็บรูป
                          ▲
 เจ้าของฟาร์ม  ──▶  หลังบ้าน /admin  (ต้องล็อกอิน, ใช้บนมือถือได้)
```

repo เดียว deploy ที่เดียว ใช้โดเมนเดียว

## หลักการออกแบบ

1. **แยกข้อมูลสาธารณะออกจากข้อมูลหลังบ้านตั้งแต่ชั้น query:** หน้าสาธารณะเรียกเฉพาะฟังก์ชัน `public*` ที่เลือกฟิลด์แบบ allowlist และมี test ยืนยันว่า `purchase_price`, `supplier`, `for_sale`, `customer` ไม่หลุดออกไป
2. **Business logic เป็น TypeScript ธรรมดา** ไม่ผูกกับ runtime เพื่อให้ย้ายผู้ให้บริการได้
3. **ห้ามลบประวัติ:** รังที่ล่มหรือขายแล้วเปลี่ยนแค่สถานะ และทุกการแก้ไขบันทึก audit log
4. **API บันทึกซ้ำได้อย่างปลอดภัย (idempotency key)** กันการกดซ้ำตอนเน็ตในสวนไม่ดี
5. **ย่อรูปบนเครื่องผู้ใช้ก่อนอัปโหลด** (ประมาณ 1600px, WebP) ส่วนวิดีโอใช้ YouTube
6. **แยก environment:** local / production ใช้ฐานข้อมูลแยกกัน (ยังไม่มี preview) · ระบบจริงคือที่เก็บข้อมูลหลัก ข้อมูลไหลจากระบบจริงลงเครื่องได้ทางเดียว (กู้ backup มาทดสอบ)
7. **ภาษาไทยเป็นหลัก:** แสดงวันที่เป็น พ.ศ. แต่เก็บเป็น ISO, ใช้เขตเวลา Asia/Bangkok

## โครงโฟลเดอร์

```
metafarm/
├─ src/
│  ├─ pages/          หน้าสาธารณะ + /admin
│  ├─ components/     ส่วนประกอบหน้า (ContactButtons, Article, CreditPhoto, MonthChart …)
│  ├─ layouts/        PublicLayout, AdminLayout
│  ├─ scripts/        JS ฝั่งเบราว์เซอร์ (ย่อรูป, อัปโหลด, คิวรอส่ง, ฟอร์มหลังบ้าน)
│  ├─ server/         queries (public / admin), services, auth
│  ├─ db/schema.ts    Drizzle schema
│  ├─ lib/            โค้ดกลาง เช่น thai-date.ts
│  └─ config/site.ts  ชื่อฟาร์ม + ที่อยู่ (ช่องทางติดต่ออยู่ในตาราง settings)
├─ drizzle/           ไฟล์ migration (SQL) ที่สร้างจาก schema
├─ content/           Markdown: pages (ชันโรง น้ำผึ้ง นโยบาย), learn (งานวิจัย), training
├─ scripts/           import-excel/, check-*.mjs (ตรวจในเบราว์เซอร์), backup, สร้างผู้ใช้
├─ docs/  design/  private/ (ไม่ขึ้น git)
├─ wrangler.jsonc     binding: DB (D1), MEDIA (R2)
```

## ฐานข้อมูล: แก้ schema อย่างไร

1. แก้ `src/db/schema.ts`
2. `bun run db:generate` สร้างไฟล์ SQL ใหม่ใน `drizzle/` (commit ไฟล์นี้)
3. `bun run db:migrate:local` · ระบบจริงใช้ migration ใน workflow `deploy.yml` ก่อน deploy (migration ต้อง**เพิ่มอย่างเดียว** ดู runbook)

## หมายเหตุสำหรับ Phase 3 (deploy) — จัดการแล้ว

- binding SESSION (KV) และ IMAGES ปิดแล้ว (`session: false`, `imageService: 'passthrough'` — D16)
- `wrangler.jsonc` ใช้ database_id จริงแล้ว (ขึ้นระบบ 2026-10-05)
- รูปสาธารณะเสิร์ฟผ่าน `/img/*` (ด้านล่าง) ส่วน `/media/*` ยังต้องล็อกอิน

## รูปและวิดีโอ

- **ชนิด/จำนวนสูงสุดต่อรัง:** รูปสมุดพก 6, รูปสำหรับขาย 6 (2 ชุดแยกกัน อัปโหลดและเรียงลำดับแยกกัน — เจ้าของขอ 2026-10-14), วิดีโอ 1 (ตามที่เจ้าของฟาร์มกำหนด) · รูปที่ 1 ของสมุดพก = มุมกว้างเห็นที่ตั้งรังเพื่อช่วยเดินหา, รูปที่ 1 ของรูปขาย = เปิดฝาโชว์ข้างในรังผ่านพลาสติกใสเพื่อโชว์ประชากรชันโรง · เรียงลำดับด้วยลากวางเหมือนแกลเลอรี — ค่าอยู่ที่ `LIMITS` ใน `src/lib/media.ts`
- **อัปโหลด:** เบราว์เซอร์ย่อรูปก่อนส่ง (`src/scripts/resize-image.ts`) แล้ว server ตรวจซ้ำ: ชนิดไฟล์จาก**ไบต์จริง** (JPEG/PNG/WebP เท่านั้น ไม่รับ SVG/GIF) ไม่เชื่อชื่อไฟล์หรือ Content-Type, ขนาด ≤ 6 MB, ครั้งละ ≤ 6 ไฟล์
- **ที่เก็บ:** R2 คีย์ `hives/<รหัสรัง>/<ชนิด>-<uuid>.<นามสกุล>` ถ้าบันทึกฐานข้อมูลล้มเหลวจะลบไฟล์ที่เพิ่งเขียนทิ้ง
- **วิดีโอ (ไฟล์):** อัปโหลดจากหลังบ้านเป็น `PUT` body ตรง ๆ (`src/scripts/video-upload.ts` → `/admin/hives/:code/video`, `/admin/settings/video`) สตรีมเข้า R2 ด้วย `FixedLengthStream` ไม่อ่านเข้าหน่วยความจำ (Worker 128 MB; body ต่อคำขอราว 100 MB จึงจำกัด **90 MB** — `MAX_VIDEO_BYTES` ใน `src/lib/video.ts`) · ตรวจ Origin เอง (PUT ไม่ใช่ฟอร์ม Astro จึงไม่ตรวจให้)
  - รับเฉพาะ MP4/MOV ที่ภาพเป็น **H.264** (`avc1`/`avc3`): HEVC ของ iPhone เล่นไม่ได้บนหลายเครื่อง → ปฏิเสธพร้อมวิธีตั้งค่า "เข้ากันได้มากที่สุด" · parser อ่านกล่อง `moov` (อาจอยู่ท้ายไฟล์) ใน `src/lib/video.ts` ทั้งฝั่งเบราว์เซอร์และเซิร์ฟเวอร์ (อ่านเป็นช่วงจาก R2)
  - **ลบพิกัด GPS** ในเบราว์เซอร์ก่อนส่ง (กล่อง `©xyz`/`loci` → `free` + สตริง ISO 6709 → ศูนย์ ขนาดไฟล์เท่าเดิม) แล้วเซิร์ฟเวอร์ตรวจซ้ำ ยังเจอพิกัด = ปฏิเสธและลบไฟล์
  - **ภาพปก:** เบราว์เซอร์ดึงเฟรม (~1 วินาที) ส่งตามหลังวิดีโอ เก็บเป็น `.jpg` ชื่อเดียวกัน (ไม่ได้ก็ข้าม) · หน้าแรกแสดงหัวข้อ "ชมวิดีโอแนะนำฟาร์ม (N วินาที)" เหนือวิดีโอ
  - เก็บที่ `videos/<hive-CODE|home>/<uuid>.mp4` · เล่นผ่าน `/video/*` (รองรับ `Range`/206 — iOS ต้องใช้) เฉพาะคีย์ที่ผูกไว้ (`hive_media` kind=video หรือ `settings.home.videoKey`) · ไม่มีคิวรอส่งแบบรูป (ไฟล์ใหญ่) — สัญญาณหลุดให้ส่งใหม่
  - ทางเลือก: ลิงก์ YouTube (unlisted) เก็บรหัส 11 ตัวอักษร · เปลี่ยนไปมาแล้วลบไฟล์เดิมใน R2 ให้
- **รูปสาธารณะ:** `/img/*` เสิร์ฟเฉพาะคีย์ที่อยู่ใน `hive_media` และเข้าเงื่อนไข (รูป `passport` ทุกรัง, รูป `sale` เฉพาะรังที่ตั้งขายและยังไม่ขาย) เดาชื่อไฟล์ไม่ได้ ส่วน `/media/*` ยังเป็นของหลังบ้าน (ต้องล็อกอิน)

## ข้อมูลสาธารณะ (กันข้อมูลลับรั่ว)

- หน้าสาธารณะอ่านข้อมูลผ่าน `src/server/public.ts` เท่านั้น ทุก query **เลือกคอลัมน์แบบ allowlist** (ห้าม `select()` เปล่า) และเหตุการณ์ส่ง `note` ออกไปเฉพาะชนิด `note` ที่เจ้าของฟาร์มติ๊กแสดง
- ที่มาของรังที่ซื้อแสดงแค่ **จังหวัด** (`provinceOf`) ปริมาณน้ำผึ้งไม่แสดง
- **ทุกครั้งที่แก้ `public.ts` หรือหน้าสาธารณะ ให้รัน `bun run check:leaks`** มันดึงข้อมูลลับจริง (ชื่อ/เบอร์คู่ค้า หมายเหตุภายใน ชื่ออำเภอ/ตำบลผู้ขาย) แล้วสแกนทุกหน้าสาธารณะ ตัดวลีทั่วไปออกและแสดงรายการที่ตัดให้ตรวจ
## สินค้าและการขาย

- **รังสมบูรณ์** ไม่อยู่ในตารางสินค้า: คือรังที่ `for_sale = 1`, `status = active` และ `sale_price > 0` (`getSaleHives`) พอขายแล้ว/เลิกตั้งขาย หน้าสินค้าปิดทันที
- **รังเปล่า / น้ำผึ้ง** อยู่ในตาราง `products` + `product_variants` (ใส่ตั้งต้นด้วย `bun run products:seed:local` รันซ้ำได้ ไม่ทับราคาที่แก้แล้ว)
- **ราคาตัวอย่าง:** `product_variants.price_confirmed` = 0 → เว็บแสดงป้าย "ราคาตัวอย่าง" · บันทึกราคาในหลังบ้านแล้วเป็น 1
- **สต็อก:** เก็บตัวเลขจริงในฐานข้อมูล แต่เว็บส่งออกแค่ `inStock` (มี/ไม่มี) — `check:leaks` ตรวจว่าตัวเลขสต็อกไม่โผล่
- **สั่งซื้อ:** ทางไลน์เท่านั้น (ปุ่มใส่ข้อความ "สนใจรัง A25 ราคา …" ให้) ยังไม่มีตะกร้า/ชำระเงินออนไลน์ (Phase 4–5)
