## Context

หลังบ้านโตขึ้นทีละหน้าตาม feedback ของเจ้าของ ผลที่ได้คือ

- **เมนูข้างบนคอมมี 17 รายการ + ลิงก์ท้ายอีก 3** (`src/layouts/AdminLayout.astro:41-65`) จอเตี้ยต้องเลื่อนดูเมนู
- หลายหน้ามีทางเข้าซ้ำกัน
  - "สินค้าและราคา" อยู่ทั้งในกลุ่มขาย, ใน SalesTabs และใน "แก้หน้าเว็บ" ของ `/admin/more`
  - "ลูกค้า" กับ "รายงาน" อยู่ทั้งในเมนูข้างและใน SalesTabs
  - "เตรียมเปิดเว็บ" อยู่ 4 ที่
- **ข้อมูลซ้ำกันข้ามหน้า**
  - หน้าภาพรวมทำซ้ำหน้า "ผลผลิตและอากาศ": การ์ดผลผลิตปี, กราฟน้ำผึ้ง และรายการรังที่ให้น้ำผึ้งมากที่สุด
  - เรื่อง "???" กับ "รอถ่ายรูป" เตือนอยู่ 4–5 ที่
- **ข้อความอธิบายยาวและซ้ำ**
  - hint ใต้ทุกขนาดสินค้าใน `products.astro:311`
  - วิธีลากเรียงรูปซ้ำกันใน products, gallery และ media
  - ข้อความก่อนเปิดเว็บ ("ข้อมูลตัวอย่าง", "ยืนยัน") ยังค้างอยู่ ทั้งที่เปิดเว็บแล้วตั้งแต่ 2026-10-05
- **บางหน้าแน่นมาก**
  - หน้ารัง `hives/[code].astro`: มี 6 ฟอร์มพับได้ + ปุ่มลบสีแดงทุกแถวประวัติ
  - `products.astro`: ประมาณ 20 ฟอร์มในหน้าเดียว
  - `todo.astro`: ประมาณ 60 ฟอร์มเมื่อมีรังค้าง 20 รัง
  - `users.astro`: แต่ละคนมี 4–5 ฟอร์ม

**เป้าหมาย:** ให้เจ้าของ (ไม่ถนัดเทคโนโลยี) เจอสิ่งที่ต้องทำได้ทันที เมนูหลักเหลือน้อยและเหมือนกันทั้งคอมและมือถือ ใช้รูปแบบที่คนคุ้นเคยจากแอปทั่วไป:

- แท็บย่อยในหมวด
- ปุ่มหลักอยู่บนสุด
- ปุ่มลบเป็นปุ่มรอง
- คำอธิบายบรรทัดเดียว

**ขอบเขตที่ตกลงแล้ว:**
- ทำได้: ปรับเมนู, ลดข้อความ, จัดวางหน้าใหม่
- **ห้าม**เปลี่ยน schema, ตรรกะข้อมูล หรือ URL เดิม (ทุก route เดิมต้องใช้ได้เหมือนเดิม)
- "เตรียมเปิดเว็บ" ย้ายออกจากเมนูข้างและหน้าภาพรวม ไปอยู่ใต้ "เมนู" โดยหน้าภาพรวมแสดงแถวเตือนเฉพาะตอนที่ยังมีรายการค้าง

## ข้อห้าม / สิ่งที่ต้องคงไว้ (จาก CLAUDE.md, ห้ามพัง)

- **สิทธิ์:** พนักงานต้องไม่เห็นเมนูหรือหน้าที่เกี่ยวกับเงิน ลูกค้า หรือออเดอร์ ให้ใช้ `canManageFarm` / `canManageUsers` และ `OWNER_KEYS` ใน AdminLayout เหมือนเดิม แล้วรัน `check:staff`
- **`/admin/todo`:** กล่อง "ไม่ทราบจริง ๆ: <topic>" ต้องแสดงตลอด (ห้ามพับเก็บ) และข้อความบนปุ่มต้องเหมือนเดิม
- **หน้ารัง:**
  - id ฟอร์ม `form-<intent>` และ deep link `?do=honey#form-honey` ต้องยังใช้ได้
  - ฟอร์มยังมี `data-outbox`, `idem` แยกต่อฟอร์ม และ `data-confirm` เหมือนเดิม
- **ปุ่มและช่องกรอก:**
  - ทุกปุ่ม/ลิงก์ที่กดได้สูงอย่างน้อย `min-h-11` (44px) และช่องกรอกตัวอักษร 16px
  - ไอคอนใช้ `<Icon>` เท่านั้น ห้ามใช้ emoji
- **ข้อความ error:** `<p class="error">` อยู่ใน wrapper เดียวกับ input ของมัน (`admin-forms.ts`) และห้ามเขียน confirm/lock handler แยกต่อหน้า
- **ชื่อเมนู:** ใช้ชื่อเดียวกันทุกที่ ถ้าเปลี่ยนชื่อ ต้องแก้ CLAUDE.md (หัวข้อ "Admin menu names" / "Admin menu v2") และ `docs/04-sitemap.md` ใน commit เดียวกัน
- **คำในหน้าแอดมิน:** ภาษาไทยง่าย ๆ บอกว่าต้องทำอะไร ไม่มีคำเทคนิคภาษาอังกฤษ hint หนึ่งบรรทัด หนึ่งเรื่อง
- **ไม่ใช้ HTML5 DnD:** การลากเรียงรูปใช้ `gallery-sort.ts` ตัวเดิม
- **commit:** commit บน `main` และอัปเดต docs (`docs/00-roadmap.md`, `docs/04-sitemap.md`, CLAUDE.md) ใน commit เดียวกับโค้ดที่เปลี่ยน

## 1. โครงเมนูใหม่ (ทำก่อน: กระทบทุกหน้า)

### 1.1 เมนูหลักชุดเดียวกันทั้งคอมและมือถือ

| เมนูหลัก | ลิงก์ | แท็บย่อยในหน้า (component ใหม่ `SubTabs`) |
|---|---|---|
| ภาพรวม | `/admin` | – |
| รัง | `/admin/hives` | รังทั้งหมด · รอถ่ายรูป (N) · ข้อมูลไม่ครบ (N) → `/admin/photos`, `/admin/todo` |
| จดบันทึก | `/admin/quick` | – |
| น้ำผึ้ง | `/admin/lots` | น้ำผึ้ง (ล็อต) · ผลผลิตและอากาศ → `/admin/production` |
| ขาย *(เจ้าของ/แอดมิน)* | `/admin/orders` | ออเดอร์ · ลูกค้า · สินค้าและราคา · รายงาน (SalesTabs เดิม) |
| หน้าเว็บ *(เจ้าของ/แอดมิน)* | `/admin/settings` | ติดต่อและชำระเงิน · หน้าแรกและหลักสูตร · รูปแกลเลอรี |

- **เมนูข้าง (คอม):** เหลือ 6 รายการข้างบน **ไม่มีหัวกลุ่ม** ลบ `sideGroups` ทิ้ง ใช้ list เดียว
  - ท้ายเมนู: ชื่อผู้ใช้ (→ บัญชี) · คนใช้งานระบบ (owner) · **เมนูอื่น ๆ** (→ `/admin/more`) · ดูหน้าเว็บจริง · ออกจากระบบ
  - เมนูสั้นลงแล้ว จึงเอาปุ่ม `data-side-more` ("เลื่อนดูเมนูเพิ่ม") และสคริปต์ของมันออกได้
  - ปี 2026-10-14 เจ้าของไม่อยากได้ปุ่ม "เมนู" บนคอม ตอนนี้ให้เป็นลิงก์เล็กด้านท้ายแทนปุ่ม ให้ระบุเรื่องนี้ใน commit message เพื่อให้เจ้าของทักได้
- **แถบล่าง (มือถือ):** ยังเป็น 5 ช่องเหมือนเดิม คือ ภาพรวม · รัง · ➕จดบันทึก · ขาย (staff: น้ำผึ้ง) · เมนู
- **`tabActive` / `active`:** ใน AdminLayout ให้ map หน้าลูกไปหาเมนูแม่ เช่น photos/todo/new → รัง, production → น้ำผึ้ง, gallery/settingsHome → หน้าเว็บ

## 2. หน้าภาพรวม `src/pages/admin/index.astro`

ลำดับใหม่ (สั้นลงประมาณครึ่งหนึ่ง):

1. แถบตัวเลข 5 ตัวเหมือนเดิม
   - มือถือแสดง label เล็ก (`text-xs`) และตัวเลข `text-xl` ให้พอดีจอ 360px
2. การ์ด "เดือนนี้" 3–4 ใบเหมือนเดิม
3. **"สิ่งที่ต้องทำ"**: แสดงเฉพาะแถวที่ค่า > 0
   - รอชำระ · รอส่ง · ข้อมูลไม่ครบ · รอถ่ายรูป
   - **เตรียมเปิดเว็บ**: แสดงเฉพาะเมื่อ `readiness` ยังมีรายการไม่เสร็จ (ใช้ `src/server/readiness.ts` ตัวเดิม) และบอกจำนวนที่เหลือ
   - ถ้าไม่มีอะไรค้างเลย ให้แสดงบรรทัดเดียว "ไม่มีงานค้าง"
4. กราฟ 2 อันเหมือนเดิม
5. เหตุการณ์ล่าสุด
   - **ลดเหลือ 5 รายการ** แล้วมีลิงก์ "ดูทั้งหมด"

**สิ่งที่ตัดออก** (ซ้ำกับหน้าผลผลิต/รายงาน):
- "รังที่ให้น้ำผึ้งมากที่สุด" (มีใน production แล้ว)
- การ์ด "ผลผลิตปี"
- ส่วนการขายรัง
- ตาราง "อัตรารอดตามที่มา": ย้ายไปท้าย `production.astro`
  - ย้าย query `d.byOrigin` ตามไปด้วย หรือเรียก `getDashboard` ที่หน้านั้น

## 3. หน้ารัง

### 3.1 `hives/[code].astro` (หน้าที่สำคัญที่สุด)

- **ส่วน "บันทึกงาน":** รวม 4 ฟอร์มเป็นการ์ดเดียว
  - ฟอร์มทั้ง 4: เก็บน้ำหวาน · เก็บไข่นางพญา · แยกไข่อ่อน · หมายเหตุ
  - ด้านบนเป็นปุ่มเลือกงานแบบ segmented ใช้ `<details name="record">` (exclusive accordion ใช้ได้โดยไม่ต้องมี JS) **เปิดได้ทีละงาน**
  - ห้ามเปลี่ยน id `form-<intent>`
  - สคริปต์ที่เปิดฟอร์มจาก `?do=` / hash ต้องยังทำงาน
  - ให้ลองเปรียบเทียบกับหน้า `quick.astro` ที่มีปุ่มงาน 7 ปุ่มอยู่แล้ว (ปุ่มใหญ่ 2 คอลัมน์ เป็นรูปแบบที่เจ้าของใช้ได้ดี) แล้วใช้หน้าตาปุ่มแบบเดียวกัน
- **ส่วน "จัดการรัง":** ตั้งขาย + เปลี่ยนสถานะ
  - พับไว้เป็นค่าเริ่มต้น
  - ลิงก์ "จดออเดอร์" เหลือที่เดียว
  - ตัด hint ยาวที่บรรทัด 321 เหลือ "ขายให้ลูกค้าที่ทักมา → กด จดออเดอร์"
- **ประวัติ:** ปุ่มลบสีแดงเต็มปุ่มในทุกแถว → เปลี่ยนเป็นปุ่มไอคอนถังขยะสีเทา (`btn-ghost`, ขนาด 44px, มี `aria-label`)
  - ยังใช้ `data-confirm` เหมือนเดิม
  - แสดงเฉพาะแถวที่ `canDeleteRecord` อนุญาต (คงเดิม)
- **ข้อความ:**
  - บรรทัด 159: ข้อความเตือนรูปขาย → "ยังขาดรูปขาย N รูป + วิดีโอ" + ลิงก์ "เพิ่มรูป"
  - บรรทัด 234: → "บันทึกย้อนหลังได้"
  - บรรทัด 273: เหลือ "พิมพ์แค่เลขก็ได้"
  - บรรทัด 303: "ราคาขายเฉลี่ย…" **ต้องตรวจก่อน** ว่าตัวเลขคำนวณจริงหรือ hard-code ถ้า hard-code ให้ลบทิ้ง
- **ลำดับบนมือถือ:**
  1. สรุปรัง + รูป
  2. บันทึกงาน
  3. ข้อมูลรัง
  4. ประวัติ
  5. จัดการรัง (ท้ายสุด)
