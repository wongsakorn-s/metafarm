## Project: MetaFarm

Website + back office for a stingless bee (ชันโรงขนเงิน) farm. Plans and decisions live in `docs/` (Thai); read `docs/07-decisions.md` and `docs/03-data-model.md` before changing data or features.

- Stack: Astro 7 + Tailwind 4 on Cloudflare Workers (no React — removed 2026-10-10; client code is plain TS in `<script>`), D1 (Drizzle, `src/db/schema.ts`), R2. Package manager: npm. Git: work and commit on `main` only.
- After every change, update the docs in the same commit (README, CLAUDE.md, `docs/00-roadmap.md`, `03-data-model.md`, `04-sitemap.md`, `10-deploy-runbook.md`, `09-research-notes.md`, `content/README.md` as relevant).
- One-off production data fixes are SQL files in `scripts/prod-data/` (idempotent, guarded, audit-logged, dry-run with `--local` first); the user runs them with `--remote` unless they explicitly ask Claude to.
- **Production is live** (https://metafarm.wong-saengsurasak.workers.dev, since 2026-10-05) and is the source of truth: the owner enters real data there. Never use `--remote` wrangler commands, deploy or backup workflows yourself — the user runs them. Never apply `seed.sql` or `snapshot.sql` to production (they `DELETE FROM` every content table; both start with `localOnlyGuard()` from `scripts/local-only-guard.ts`, which aborts when the DB has a non-`@metafarm.local` user — keep local accounts on that domain).
- `private/` is gitignored and contains supplier PII; never copy its contents into tracked files, tests, or public pages.
- Fields marked 🔒 in `docs/03-data-model.md` (purchase price, supplier, for_sale, customer, notes) must never reach public pages.
- Dates: store ISO `YYYY-MM-DD`, display Buddhist Era via `src/lib/thai-date.ts`.
- Checks: `npm run check`, `npm test`, `npm run build`. Server tests (`src/server/*.test.ts`) use `testDb()` from `src/server/test-d1.ts`: a temporary miniflare D1 with every migration in `drizzle/` applied (`until` stops before one, to test data backfills).
- Orders and hives: `hive_holds` ties a hive to one non-cancelled order (insert with the order, delete on cancel); manual hive status/sale changes must pass `holdBlocks()` (`src/lib/orders.ts`). Order transitions use a once-key per source status (`onceKey` in `src/server/orders.ts`).
- Back office lives under `src/pages/admin/` (SSR, `prerender = false`); auth in `src/server/auth.ts` + `src/middleware.ts`; all DB access for hives in `src/server/hives.ts`; form validation in `src/lib/validation.ts` (Zod).
- Admin pages use the full content width (owner asked, 2026-10-10); long forms lay fields out in two columns on desktop (`grid lg:grid-cols-2`, notes/save bar `lg:col-span-2`). Keep hints to one short line. Farm stats (home only — removed from passport 2026-10-10) use `components/FarmStats.astro`. Passport browse grid = `getSampleHives` (random, only hives with photo + complete data).
- Roles: owner · admin · staff — see the Roles (Phase 5.1) note below. Owners change others' roles (never their own, so one owner always remains); a role change ends that user's sessions.
- Tailwind 4: shared classes (`btn`, `card`, `field`…) are `@utility` in `src/styles/global.css`, not `@layer components`.
- Local login: `npm run user:create -- --email owner@metafarm.local --generate` (password written to `private/dev-owner.txt`).

Login throttle (5.2): `src/lib/auth/throttle.ts` — 3 hashed keys in `login_attempts` (email+IP 5, email 10, IP 30 per 15 min); locked logins never verify the password; owner can unlock other users.
- Concurrency (5.3): overwrite-style forms send `version` (= `updated_at`) and update `WHERE updated_at = version` with `auditIfChanged` in the same batch (`src/server/versioned.ts`); on conflict render `components/ConflictNotice.astro`. Multi-statement actions that must run once (order paid/fulfilled/cancelled) start their batch with `once(db, key)` (`once_keys` PK) and treat `isOnceConflict` as already done. `db.batch` accepts only query builders — not `db.run(sql)`. When a batch acts on a value read before it (hive status, holds), put `abortIf(db, <changed?>)` (`src/server/versioned.ts`) first: it rolls back the whole batch and is caught with `isGuardAbort` — `statusStatements` does this for hive status (so pay/cancel/status forms never overwrite a status changed by another device), and `updateSale` for status + holds. A new customer from the order form is inserted inside the order batch (`last_insert_rowid()`), never before it. Other overwrite guards: customer edit (`version`), order note (`prevNote` = note seen, so paying meanwhile is not a conflict), hive sale form (`seen` = `saleSeen()`), every `/admin/settings` form (`version` = `settingsVersion()`, checked with `abortIf`). `user:create --print-sql` sets `must_change_password = 1`.
- Contact buttons (5.4): never hard-code LINE links on public pages — use `components/ContactButtons.astro` / `contactActions()` (`src/lib/contact.ts`), which follow `contact.primary` and hide blank channels. Messenger links copy the message before opening (m.me ignores `?text=` on many clients).
- Outbox (5.5): hive record forms carry `data-outbox` and photo uploads call `sendOrQueue` (`src/scripts/outbox.ts`); the endpoint must answer JSON when `wantsJson(request)` (`{ok, message, redirect}` / 422 `{ok:false, message}`) and be idempotent (idem / batch) because the queue re-sends. Store files as ArrayBuffer, not Blob (WebKit). Test with `npm run check:offline` and `-- --webkit`.
- Hive codes: 1–3 letters + number (A25, B12, G108), any order; `src/lib/hive-code.ts` (`normalizeHiveCode`, `HIVE_CODE_RE`) is the only place that defines the format. `hives.id` is independent of the code (DB-assigned for new hives; existing A-hives keep id = number). Sort with `byCode()` from `src/server/hives.ts`, never `hives.id`, when users see the order.
- SQL gotcha: in single-table drizzle selects a column interpolated as `${hives.id}` renders as bare `"id"`; inside a correlated subquery SQLite binds it to the inner table. Always write the outer table name literally (`m.hive_id = hives.id`); `src/server/sql-correlation.test.ts` enforces it.
- Do not run `astro build` / `astro check` while a dev server is running: it invalidates Vite's dep cache and the running server then 500s (e.g. "file does not exist ... deps_ssr/zod.js"). Stop the dev server first, or restart it afterwards (`astro dev --force`).
